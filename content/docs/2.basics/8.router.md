## Overview
Nuxt는 내부적으로 Vue Router를 사용하지만, 개발자가 직접 `createRouter()`로 라우터 인스턴스를 만들거나 라우트 목록을 나열할 필요가 없습니다. `app/pages` 디렉토리에 Vue 파일을 추가하는 것만으로 라우트가 자동으로 생성되는 **파일 기반 라우팅**을 기본으로 제공하기 때문입니다.

::note
즉, Nuxt 프로젝트에서는 별도의 `router/index.ts`를 작성하거나 `app.use(router)`를 호출할 필요가 없습니다. `app/pages`의 폴더·파일 구조 자체가 곧 라우트 구조입니다.
::

## 1. 파일 기반 라우팅
`app/pages` 디렉토리의 파일 경로가 그대로 URL 경로가 됩니다.

```bash
app/pages/
├─ index.vue          # /
├─ about.vue           # /about
└─ blog/
   ├─ index.vue        # /blog
   └─ archive.vue       # /blog/archive
```

## 2. 동적 라우트
파일명에 대괄호(`[ ]`)를 사용하면 URL의 일부를 변수처럼 다룰 수 있습니다.

### 필수 파라미터
```bash
app/pages/
└─ blog/
   └─ [id].vue          # /blog/1, /blog/2 ...
```
```vue
<!-- app/pages/blog/[id].vue -->
<script setup lang="ts">
const route = useRoute()
</script>

<template>
  <h1>Blog Post {{ route.params.id }}</h1>
</template>
```

### Catch-all 라우트
`[...slug].vue`처럼 `...`을 붙이면 깊이에 상관없이 남은 모든 경로 세그먼트를 하나의 배열로 받을 수 있습니다.
```bash
app/pages/
└─ [...slug].vue        # /a, /a/b, /a/b/c ...
```
```vue
<!-- app/pages/[...slug].vue -->
<script setup lang="ts">
const route = useRoute()
// '/a/b/c' 접근 시 route.params.slug === ['a', 'b', 'c']
</script>
```

### 선택적 파라미터
대괄호를 두 번(`[[ ]]`) 감싸면 해당 세그먼트가 있을 때와 없을 때를 모두 매칭합니다.
```bash
app/pages/
└─ [[slug]].vue         # / 와 /hello 모두 매칭
```

## 3. `useRoute()` / `useRouter()`
- `useRoute()`: 현재 라우트 정보(`params`, `query`, `path`, `fullPath` 등)를 담은 반응형 객체를 반환합니다.
- `useRouter()`: 프로그래밍 방식 내비게이션에 사용하는 라우터 인스턴스(`push`, `replace`, `back` 등)를 반환합니다.

```vue
<script setup lang="ts">
const route = useRoute()
const router = useRouter()

console.log(route.params.id) // 동적 세그먼트 값
console.log(route.query.page) // ?page=2 같은 쿼리 파라미터

function goToList() {
  router.push('/blog')
}
</script>
```

## 4. `definePageMeta`
페이지 컴포넌트 내에서 `definePageMeta()`를 호출하면 레이아웃, 미들웨어 등 해당 페이지에 대한 메타데이터를 타입 안전하게 선언할 수 있습니다.

```vue
<!-- app/pages/admin/index.vue -->
<script setup lang="ts">
definePageMeta({
  layout: 'admin',
  middleware: ['auth'],
})
</script>
```
::tip
`definePageMeta`는 컴파일러 매크로이므로 `<script setup>` 최상단에서만 호출할 수 있으며, 빌드 시점에 정적으로 분석됩니다.
::

## 5. `navigateTo` & `<NuxtLink>`
- **`<NuxtLink>`**: 페이지 간 이동을 위한 기본 컴포넌트로, 별도의 import 없이 바로 사용할 수 있습니다. 내부적으로 `<a>` 태그로 렌더링되며 뷰포트에 들어오면 자동으로 프리페치합니다.
- **`navigateTo()`**: 컴포넌트 로직, 미들웨어, 플러그인 등에서 프로그래밍 방식으로 라우트를 이동할 때 사용하는 유틸리티 함수로, 서버와 클라이언트 양쪽에서 동작합니다.

```vue
<template>
  <NuxtLink to="/about">About</NuxtLink>
</template>
```
```ts
// 컴포넌트 로직이나 미들웨어에서
await navigateTo('/login')

// 새 탭에서 외부 URL 열기
await navigateTo('https://nuxt.com', { external: true, open: { target: '_blank' } })
```

## 6. 라우트 미들웨어
미들웨어는 특정 라우트로 이동하기 전에 실행되는 함수로, 인증 확인이나 리다이렉트 같은 로직에 사용됩니다. `app/middleware` 디렉토리를 기준으로 세 가지 유형이 있습니다.

::steps{level="3"}
### 익명(inline) 미들웨어
`definePageMeta` 안에 함수를 직접 작성하여 해당 페이지에서만 실행합니다.
```vue
<script setup lang="ts">
definePageMeta({
  middleware: [
    function (to, from) {
      // 특정 페이지에서만 실행되는 로직
    },
  ],
})
</script>
```

### 이름 있는(named) 미들웨어
`app/middleware/auth.ts`처럼 파일로 정의한 뒤, `definePageMeta`에서 이름으로 지정한 페이지에서만 실행합니다.
```ts
// app/middleware/auth.ts
export default defineNuxtRouteMiddleware((to, from) => {
  const isLoggedIn = useAuthStore().isLoggedIn
  if (!isLoggedIn) {
    return navigateTo('/login')
  }
})
```
```vue
<script setup lang="ts">
definePageMeta({
  middleware: ['auth'],
})
</script>
```

### 전역(global) 미들웨어
파일명에 `.global.ts` 접미사를 붙이면 모든 라우트 이동 시 자동으로 실행됩니다.
```ts
// app/middleware/analytics.global.ts
export default defineNuxtRouteMiddleware((to, from) => {
  // 모든 라우트 전환마다 실행
})
```
::

::warning
미들웨어 안에서 `navigateTo()`를 호출할 때는 반드시 `return`으로 결과를 반환해야 합니다. `return` 없이 호출만 하면 리다이렉트가 보장되지 않습니다.
::

## 7. 레이아웃과 중첩 라우팅
- 상위 페이지 컴포넌트 안에 `<NuxtPage />`를 배치하면 하위 라우트의 컴포넌트가 그 자리에 렌더링됩니다.
- `app/pages/parent.vue`와 `app/pages/parent/child.vue`를 함께 두면 `/parent/child` 접근 시 `parent.vue`의 `<NuxtPage />` 위치에 `child.vue`가 중첩되어 표시됩니다.

```vue
<!-- app/pages/parent.vue -->
<template>
  <div>
    <h1>Parent</h1>
    <NuxtPage />
  </div>
</template>
```

## 8. 참고: Nuxt 없이 Vite + Vue Router를 사용한다면
Nuxt를 사용하지 않는 순수 Vite + Vue 프로젝트라면 `vue-router`를 직접 설치하고 라우트를 수동으로 구성해야 합니다.
```bash[pnpm]
pnpm add vue-router@4
```
```typescript
import type { RouteRecordRaw } from 'vue-router'
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from './pages/index.vue'

const routes: Array<RouteRecordRaw> = [
  { path: '/', name: 'Home', component: HomeView },
  { path: '/user/:id', name: 'User', component: () => import('./pages/user/[id].vue') },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
})

export default router
```
```js
createApp(App).use(router).mount('#app')
```
이 경우 동적 세그먼트(`:id`)는 `route.params.id`로 접근하며, 중첩 라우트는 `children` 옵션으로 직접 구성해야 합니다. 하지만 이 프레임워크(Nuxt) 위에서 작업한다면 위 1~7번의 파일 기반 라우팅을 사용하는 것이 기본이자 권장 방식입니다.
