## Overview
Nuxt 플러그인은 애플리케이션이 부팅되는 시점에 실행되는 코드로, Vue 앱 인스턴스에 접근하여 전역 컴포넌트/디렉티브를 등록하거나, 서드파티 라이브러리를 초기화하거나, 컴포넌트 어디서든 쓸 수 있는 전역 헬퍼를 만드는 데 사용됩니다. `app/plugins` 디렉토리에 파일을 추가하기만 하면 Nuxt가 자동으로 등록합니다.

::note
`app/components`나 `app/pages`처럼 별도의 import나 `nuxt.config.ts` 등록 없이, 디렉토리에 파일을 두는 것만으로 활성화됩니다.
::

## 1. 플러그인 기본 구조
플러그인 파일은 `defineNuxtPlugin()`으로 감싼 함수를 기본 내보내기(default export)로 작성합니다.

```ts
// app/plugins/hello.ts
export default defineNuxtPlugin((nuxtApp) => {
  console.log('플러그인이 실행되었습니다!')
})
```
- 인자로 전달되는 `nuxtApp`은 Vue 앱 인스턴스와 Nuxt 런타임 컨텍스트를 함께 감싼 객체입니다.
- `nuxtApp.vueApp`을 통해 일반 Vue 애플리케이션 인스턴스(`app.component()`, `app.directive()` 등)에 접근할 수 있습니다.

## 2. 전역 헬퍼 제공하기 (`provide`)
플러그인 함수가 `provide` 속성을 가진 객체를 반환하면, `$` 접두사가 붙은 전역 헬퍼로 등록되어 애플리케이션 어디서든 사용할 수 있습니다.

```ts
// app/plugins/hello.ts
export default defineNuxtPlugin(() => {
  return {
    provide: {
      hello: (name: string) => `Hello, ${name}!`,
    },
  }
})
```
```vue
<script setup lang="ts">
const { $hello } = useNuxtApp()

console.log($hello('Nuxt')) // "Hello, Nuxt!"
</script>
```
::tip
TypeScript 환경에서 `$hello`에 대한 타입 추론까지 지원하려면, 모듈 확장(`declare module '#app'`)을 통해 `NuxtApp`과 `PluginInjection` 인터페이스에 타입을 추가해야 합니다. 자세한 방법은 Nuxt 공식 문서의 [Providing Type-Safe Helpers](https://nuxt.com/docs/guide/directory-structure/plugins#typing-plugins)를 참고하세요.
::

## 3. 클라이언트/서버 전용 플러그인
파일명에 `.client.ts` 또는 `.server.ts` 접미사를 붙이면 해당 환경에서만 플러그인이 실행됩니다.

```bash
app/plugins/
├─ analytics.client.ts   # 브라우저에서만 실행 (예: GA, 방문 트래킹)
└─ sitemap.server.ts     # 서버에서만 실행
```
::warning
`window`나 `document` 같은 브라우저 전용 API를 사용하는 서드파티 라이브러리는 반드시 `.client.ts`로 분리해야 SSR 단계에서 에러가 발생하지 않습니다.
::

## 4. 실행 순서 제어
플러그인은 기본적으로 파일명 순서대로(숫자 접두사 기준) 순차 실행됩니다. 더 세밀한 제어가 필요하면 객체 형태의 플러그인 정의에서 다음 옵션을 사용할 수 있습니다.

```ts
export default defineNuxtPlugin({
  name: 'my-plugin',
  enforce: 'pre', // 'pre' | 'default' | 'post'
  dependsOn: ['other-plugin'], // 지정한 플러그인 실행 완료 후 실행
  parallel: true, // 다른 플러그인과 병렬 실행 허용
  async setup(nuxtApp) {
    // 플러그인 로직
  },
})
```
- `enforce: 'pre'`는 다른 플러그인보다 먼저, `'post'`는 나중에 실행되도록 합니다.
- `dependsOn`에 이름을 지정한 플러그인이 먼저 완료된 뒤에 실행됩니다(의존하는 플러그인도 `name`을 명시해야 합니다).
- `parallel: true`를 사용하면 순서를 기다리지 않고 다른 플러그인과 동시에 실행되어 초기화 속도를 높일 수 있습니다.

## 5. Nuxt 앱 훅과 연동하기
`nuxtApp.hook()`을 사용하면 플러그인 안에서 앱의 생명주기 이벤트(페이지 전환, 마운트 완료 등)를 구독할 수 있습니다.

```ts
// app/plugins/page-tracker.client.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('page:start', () => {
    console.log('페이지 전환 시작')
  })

  nuxtApp.hook('app:mounted', () => {
    console.log('앱 마운트 완료')
  })
})
```
::note
사용 가능한 훅 목록은 Nuxt 공식 문서의 [Lifecycle Hooks](https://nuxt.com/docs/api/advanced/hooks)에서 확인할 수 있습니다.
::

## 6. 실전 예시: 서드파티 라이브러리 통합
```ts
// app/plugins/toast.client.ts
import Toast, { POSITION } from 'vue-toastification'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(Toast, {
    position: POSITION.TOP_RIGHT,
  })
})
```
전역 컴포넌트, 디렉티브, UI 라이브러리 등 Vue 플러그인 생태계의 기능을 이 방식으로 Nuxt 애플리케이션에 그대로 연결할 수 있습니다.

## 7. 베스트 프랙티스
- 브라우저 전용 라이브러리는 `.client.ts`로 분리해 서버 번들에 포함되지 않도록 합니다.
- 무거운 초기화 로직은 필요한 시점에 동적 `import()`로 불러와 초기 부팅 속도를 지키는 것이 좋습니다.
- 단순히 값 하나를 여러 컴포넌트에서 공유하려는 목적이라면 플러그인보다 [Composable](/docs/intermediate)이나 [Pinia 스토어](/docs/intermediate/state)가 더 적합할 수 있습니다. 플러그인은 "앱 전체의 부트스트랩 로직"에 집중하는 것이 유지보수에 유리합니다.
